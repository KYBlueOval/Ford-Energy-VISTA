# VISTA 2.3.3 — Shift Handoff and Reconciliation

## Deployment

1. Replace the Apps Script `Code.gs` with `apps-script/Code.gs` from this release.
2. Save the Apps Script project.
3. Run `setupVista()` once. This creates the `ShiftHandoffs` sheet without replacing existing data or configuration values.
4. Create a new web-app deployment version and retain the existing web-app URL.
5. Deploy the repository contents to GitHub Pages.
6. Hard-refresh Home, Visitor Registration, Security Operations, and Administration with `Ctrl + F5`.

## Verification

1. Sign in to Security Operations as Security, Front Desk, Security Supervisor, Admin, or Super Administrator.
2. Confirm the Live Site Accountability refresh control uses the Ford-blue icon treatment.
3. Confirm every active visitor has a Ford-blue `Open / Check Out` action.
4. Check in a visitor and assign a badge; optionally mark a test badge Lost or Broken.
5. Enter a shift/post label and meaningful handoff notes.
6. Select `Record Shift Handoff`.
7. Confirm the new handoff appears under Recent handoffs with the onsite, badges-out, overdue, and exception counts captured at submission time.
8. Confirm a row was appended to `ShiftHandoffs` and `SHIFT_HANDOFF_CREATED` appears in `AuditLog`.
9. Check the visitor out, record a second handoff, and confirm the new snapshot reflects the reconciled state without changing the first snapshot.

## Regression checks

- Visitor approval, denial, and no-show permissions remain role restricted.
- Badge assignment requires an Approved visit and an Available badge.
- Checkout verifies the returned UID and records badge condition.
- Visitor and user photographs continue loading through authenticated endpoints.
- Production folder IDs, web-app URLs, authentication settings, and branding assets remain unchanged.
