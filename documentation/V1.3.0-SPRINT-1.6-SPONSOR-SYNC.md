# VISTA v1.3.0 Sprint 1.6 — Google Sheets Sponsor Synchronization

## Purpose

The `Sponsors` worksheet remains the single administrative source. GitHub Actions retrieves the public Apps Script `listSponsors` endpoint every five minutes and updates `public-registration/data/sponsors.json` for the public registration page.

## Worksheet columns

Use these headers exactly:

`SponsorID | SponsorName | SponsorEmail | Department | Active | SearchKeywords | LastUpdatedAt`

Only rows with a name, email, and an `Active` value other than `No`, `False`, `0`, `Inactive`, or `Disabled` are published.

## First-time GitHub setup

1. Upload the Sprint 1.6 repository files, including the hidden `.github` folder.
2. Open the repository on GitHub.
3. Select **Settings → Actions → General**.
4. Under **Workflow permissions**, select **Read and write permissions**.
5. Save.
6. Select **Actions → Sync VISTA Sponsors → Run workflow**.
7. Confirm the run finishes with a green check.
8. Open `public-registration/data/sponsors.json` and verify the worksheet entries appear.

The workflow uses the production Apps Script URL by default. To change it later, create the repository variable `VISTA_SPONSOR_API_URL` under **Settings → Secrets and variables → Actions → Variables**.

## Normal use

Edit the `Sponsors` worksheet only. Changes synchronize within approximately five minutes. To publish immediately, use **Actions → Sync VISTA Sponsors → Run workflow**.

## Troubleshooting

- A red workflow run: open the failed run and inspect **Synchronize sponsor directory**.
- No commit: the generated sponsor data matched the existing JSON.
- Zero sponsors: the workflow intentionally fails and preserves the last working JSON.
- Sponsor not shown: confirm `Active` is `Yes`, and that both name and email are present.
