# VISTA v1.3.0 Sprint 1.6.1 — GitHub Actions Sponsor Sync Fix

This corrective release adds the missing GitHub Actions workflow and makes the Google Sheets `Sponsors` tab the operational source of truth for the public registration sponsor picker.

## Data flow

`Sponsors` worksheet → Apps Script `listSponsors` endpoint → GitHub Actions → `public-registration/data/sponsors.json` → public registration search.

## One-time GitHub setup

1. Upload the full repository package, including the hidden `.github` folder.
2. In GitHub, open **Settings → Actions → General**.
3. Under **Workflow permissions**, select **Read and write permissions** and save.
4. Open the **Actions** tab.
5. Select **Sync VISTA Sponsors**.
6. Select **Run workflow**, choose `main`, and run it.
7. Open `public-registration/data/sponsors.json` and verify that every active sponsor from the worksheet is present.

## Optional repository variable

The workflow already contains the current production Apps Script URL. To override it later without editing the workflow:

1. Open **Settings → Secrets and variables → Actions → Variables**.
2. Create `VISTA_SPONSOR_API_URL`.
3. Set it to the current Apps Script `/exec` URL.

## Ongoing use

- Add or edit sponsors only in the `Sponsors` worksheet.
- Set `Active` to `Yes` to publish a sponsor.
- Set `Active` to `No` to remove a sponsor from public search while preserving historical records.
- The workflow checks every five minutes.
- Use **Actions → Sync VISTA Sponsors → Run workflow** for an immediate refresh.

## Required worksheet headers

`SponsorID`, `SponsorName`, `SponsorEmail`, `Department`, `Active`, `SearchKeywords`, `LastUpdatedAt`.

## Verification

The workflow must show a green check. The generated JSON should contain a `count` equal to the number of active, valid sponsor rows. The public registration search placeholder should then show the same number of saved sponsors.
