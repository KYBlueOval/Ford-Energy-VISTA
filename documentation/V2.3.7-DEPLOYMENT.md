# VISTA 2.3.7 — Mobile Operations and Incident Response

## Included

- Live operational alert center for overdue visitors, lost/broken badges, and escalated shift handoffs.
- Alert acknowledgement with user, timestamp, status, and audit history.
- Security incident reporting with category, severity, location, related visitor/badge, and optional camera evidence.
- Supervisor incident resolution workflow.
- Authenticated Android NFC handoff for badge login, visitor badge assignment/return, user badge assignment, and badge inventory.
- Android camera/file capture for visitor registration and incident evidence.
- Mobile-data operation through the production HTTPS VISTA web application.

## Web and Apps Script deployment

1. Replace the Apps Script `Code.gs` with `apps-script/Code.gs`.
2. Save the Apps Script project.
3. Run `setupVista()` once.
   - This adds the `Notifications` and `Incidents` sheets.
   - It adds `INCIDENT_PHOTO_FOLDER_ID` only when the key does not already exist.
   - Existing production configuration values and roster data are not replaced.
4. Optional: set `INCIDENT_PHOTO_FOLDER_ID` to a dedicated Google Drive folder ID.
   - If blank, VISTA uses `USER_PHOTO_FOLDER_ID`, then `PHOTO_FOLDER_ID`, then the Apps Script account’s Drive root.
   - Incident files always receive unique timestamp and UUID names and do not overwrite existing files.
5. Create a new Apps Script web-app deployment version while retaining the existing web-app URL.
6. Publish the repository to GitHub Pages.
7. Hard-refresh Home, Registration, Security Operations, and Administration.

## Web proof test

1. Sign in to Security Operations.
2. Confirm the Alerts & Notifications and Incident Reporting panels display.
3. Check in a visitor whose expected departure is in the past; refresh and confirm an overdue alert appears.
4. Acknowledge the alert and verify the officer and time are shown.
5. Mark a returned badge Lost or Broken and confirm a badge exception alert appears.
6. Report an incident, optionally capture a photograph, and confirm the `Incidents` sheet receives one row.
7. Sign in as a Security Supervisor or Administrator and resolve the incident.
8. Confirm `AuditLog` contains `NOTIFICATION_ACKNOWLEDGED`, `INCIDENT_REPORTED`, and `INCIDENT_RESOLVED` events.

## Android build and test

The native project is in `android-app/`.

1. Open `android-app` in Android Studio.
2. Allow Gradle synchronization to finish.
3. Connect an NFC-capable Android device with USB debugging enabled.
4. Run the `app` configuration, or install the generated debug APK.
5. Grant Camera permission when prompted and enable NFC in Android settings.
6. Test the Home, Register, Security, and Admin navigation buttons.
7. At a signed-out Security or Admin screen, tap an authorized employee badge and verify badge login begins.
8. Open Assign Badge & Check In; tap a visitor badge and verify its UID populates the badge field.
9. Open Return Badge & Check Out; tap the issued badge and verify the return UID is populated.
10. Open Report Incident and capture a camera image.

## Android security notes

- Cleartext HTTP is disabled.
- VISTA data remains in the existing Apps Script and Google Sheets backend.
- The app does not store PINs or copy the database locally.
- NFC data is delivered only to the currently displayed VISTA workflow.
- Existing VISTA role permissions and server-side validation still control every operation.
- The included APK is a development-signed test build. A Ford-managed release key and enterprise distribution policy are required before production rollout.
