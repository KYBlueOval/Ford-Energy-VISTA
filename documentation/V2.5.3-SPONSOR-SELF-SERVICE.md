# VISTA 2.5.3 — Sponsor Self-Service & Administrator Oversight

## Included

- Admin and Super Administrator access to the Sponsor & Approver Portal.
- A visible administrator oversight banner and all-sponsor request scope.
- Server-side oversight authorization for visitor details, photographs, activity, approval, denial, cancellation, and updates.
- Sponsor/Approver scoping remains limited to direct and active delegated assignments.
- Single-visit and weekly recurring request creation from the Sponsor Portal.
- Separate Visit ID, confirmation number, email delivery, activity, and audit records for each recurring occurrence.
- Administrator selection of the accountable Sponsor or Approver.
- Administrator creation and cancellation of sponsor coverage directly from the portal.

## Deployment

1. Replace the Apps Script project `Code.gs` with `apps-script/Code.gs`.
2. Save the project.
3. Run `setupVista()` once. No new worksheet or Config key is required by 2.5.3.
4. Create a new version of the existing Apps Script web-app deployment and retain its URL.
5. Allow GitHub Pages to deploy.
6. Hard-refresh the Sponsor Portal with `Ctrl + F5`.

Existing production Config values are preserved.

## Administrator access proof-out

1. Sign into the Sponsor Portal using an active Admin or Super Administrator badge.
2. Confirm the page displays **Administrator Oversight Mode** and **All Sponsored Visitors**.
3. Open a visitor assigned to another sponsor.
4. Confirm the visitor record, photo, and activity are available.
5. Approve or deny a test request.
6. Confirm the acting administrator is recorded in `VisitActivity` and `AuditLog`.
7. Sign in as a normal Sponsor and confirm only directly assigned or actively delegated requests are visible.

## Scheduling proof-out

1. Select **Schedule a Visitor**.
2. As an administrator, select the accountable Sponsor or Approver.
3. Create one test request and confirm:
   - A `VisitRequests` row is created with status `Submitted`.
   - `SponsorSource` is `VISTA Sponsor Portal`.
   - `AgreementCompletionStatus` is `Pending Visitor Acknowledgement`.
   - Sponsor, visitor, and configured Security notifications are attempted.
   - `SPONSOR_VISIT_CREATED` appears in `VisitActivity` and `AuditLog`.
4. Approve, update, and cancel separate test records.
5. Create a two-week recurring test series and verify two unique Visit IDs and confirmation numbers.
6. Verify the requests appear in Security Operations and Sponsor Approval Governance.
7. Cancel the test occurrences when proof-out is complete.

## Access safeguards

- Security, Front Desk, and Security Supervisor accounts remain denied Sponsor Portal access.
- Administrator access is not treated as a sponsor identity; the UI and returned records identify it as administrative oversight.
- Sponsor and Approver accounts cannot choose a different accountable sponsor when creating a request.
- Administrators must select an active Sponsor or Approver for each new request.
- Recurring series are limited to 12 weekly occurrences.
- Sponsor-created records do not falsely record visitor policy acceptance. They remain marked **Pending Visitor Acknowledgement** until the visitor acknowledgement workflow is completed.
