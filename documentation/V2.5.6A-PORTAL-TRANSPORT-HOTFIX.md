# VISTA 2.5.6A - Portal Transport and Permanent Badge UI Hotfix

This corrective release addresses the Sponsor and Administration portal error `Unexpected token '<' ... is not valid JSON` and refines the Sponsor permanent-badge authorization control.

## Corrections

- Sponsor and Administration requests now validate the Google Apps Script response before parsing it.
- Timeout, connectivity, Google HTML service-page, HTTP, and application errors now produce actionable VISTA messages.
- The production Apps Script URL remains unchanged.
- The permanent-badge request action now uses the Ford-blue dimensional button treatment, including highlight, depth, hover, pressed, focus, disabled, and responsive states.
- Sponsor and Administration script assets and Sponsor permanent-badge styles use updated cache versions.

## Deployment

This is a GitHub Pages frontend hotfix. It does not require a new Apps Script deployment or a `setupVista()` run.

1. Deploy the repository files to GitHub Pages.
2. Wait for the Pages workflow to complete.
3. Hard-refresh the Sponsor and Administration portals.
4. Confirm each footer displays `Version 2.5.6A`.

## Prove-out

1. Sign in to the Sponsor Portal with a Sponsor, Approver, Admin, or Super Administrator badge or username/PIN.
2. Open an Approved, Checked In, or Checked Out visitor with an email address and photograph.
3. Confirm the `Request Permanent Badge` control has the dimensional Ford-blue treatment and opens the authorization dialog.
4. Sign in to Administration and save a non-destructive user-record update.
5. Confirm normal API responses save successfully and no raw JSON parser message appears.
6. If Google returns a temporary HTML service page, confirm VISTA reports service/deployment guidance instead of `Unexpected token '<'`.

## If the service guidance persists

Verify the Apps Script web app is deployed from the current `apps-script/Code.gs`, executes as the script owner, and is accessible to the intended users. Preserve the existing production deployment URL unless the deployment itself must be replaced.
