# VISTA Version 2.5.0 — Sponsor & Approver Portal

## Outcome

Version 2.5.0 closes the sponsor-review loop with a dedicated authenticated portal. Sponsor and Approver accounts see only visitor requests assigned to their VISTA email address or sponsor identifier.

## Capabilities

- Ford Energy badge login with username/PIN backup.
- Pending, approved/upcoming, onsite, completed, and total assigned-visitor metrics.
- Search and status filtering across assigned requests.
- Protected visitor photograph and sponsor-scoped activity timeline.
- Approve and deny decisions with documented notes.
- Cancellation before check-in.
- Eligible schedule, access-scope, escort, and restriction updates.
- Branded visitor decision emails with delivery outcome logging.
- Sponsor-review and guest-arrival email links route to the new portal.

## Security boundaries

- Only active `Sponsor` and `Approver` VISTA roles receive `sponsorPortal` permission.
- The server matches `Users.Email` to `VisitRequests.SponsorEmail`; it can also match the user's Employee ID or username to `SponsorID`.
- Direct requests for an unrelated visitor, photograph, activity timeline, update, or decision are rejected server-side.
- Sponsor timelines exclude badge activity belonging to unrelated visitors.
- Check-in, checkout, badge management, Administration, reporting, and system configuration remain unavailable to Sponsor and Approver accounts.

## Deployment

1. Replace the Apps Script project `Code.gs` with `apps-script/Code.gs`.
2. Save the Apps Script project.
3. Run `setupVista()` once. This only adds the missing `SPONSOR_PORTAL_URL` Config key and preserves existing values and records.
4. Verify `SPONSOR_PORTAL_URL` is `https://kyblueoval.github.io/Ford-Energy-VISTA/sponsor-portal/`.
5. Create a new version of the existing Apps Script web-app deployment and retain the existing URL.
6. Allow GitHub Pages to deploy, then hard-refresh with `Ctrl + F5`.

## Sponsor account preparation

The `Sponsors` worksheet controls which people visitors can select. Portal authentication uses the `Users` worksheet.

In Administration, create or edit a VISTA user with:

- Role: `Sponsor` or `Approver`
- Email: exactly the same address stored in `VisitRequests.SponsorEmail` and normally `Sponsors.SponsorEmail`
- Username and PIN
- Assigned Ford Energy Badge UID when badge login will be used
- Active account enabled

## Proof-out

1. Create a test Sponsor user whose email matches a test visitor request's sponsor email.
2. Sign in at `/sponsor-portal/` with badge and then PIN backup.
3. Confirm only that sponsor's requests are listed.
4. Open a pending request, verify the protected photo and activity timeline, and approve it with instructions.
5. Confirm the visitor status becomes `Approved` in `VisitRequests`.
6. Confirm the visitor receives the branded approval email.
7. Verify `STATUS_APPROVED` and `VISITOR_DECISION_EMAIL_SENT` in `AuditLog` and `VisitActivity`.
8. Submit another test request and deny it with a reason; confirm the visitor email and audit records.
9. Update an eligible visit's date, time, access, or escort requirements and verify `SPONSOR_VISIT_UPDATED`.
10. Cancel an eligible visit and confirm it can no longer be checked in.
11. Attempt to retrieve another sponsor's Visit ID or photo and confirm the server rejects the request.
12. Sign in with a Security, Front Desk, or Admin account and confirm the Sponsor Portal denies access.

Visitor decision email failure is non-blocking: the sponsor decision remains recorded, and VISTA logs the delivery warning for follow-up.
