# VISTA 2.5.6 — Permanent Badge Authorization

VISTA 2.5.6 adds a governed permanent-badge authorization workflow for extended-duration and frequent visitors. Sponsors and Approvers may authorize an eligible visitor for a Ford Energy Blue, Ford Energy Contractor Green, or Ford Energy OEM Orange credential. VISTA then directs the visitor to the standard Ford Energy onboarding intake and sends the authorization package to Ford Global Security.

## Deployment

1. Replace the Apps Script project `Code.gs` with `apps-script/Code.gs` from this repository.
2. Save the Apps Script project and run `setupVista()` once.
3. Review the new permanent-badge values in the `Config` worksheet.
4. Create a new Apps Script web-app deployment version while retaining the existing deployed URL.
5. Upload the repository files to GitHub and wait for GitHub Pages to finish publishing.
6. Hard-refresh the Sponsor and Administration portals with `Ctrl + F5`.

`setupVista()` creates the `PermanentBadgeRequests` worksheet and preserves existing production values and records.

## Config values

| Key | Recommended value | Purpose |
| --- | --- | --- |
| `PERMANENT_BADGE_INTAKE_URL` | `https://script.google.com/macros/s/AKfycbxnXEYqn0Ejt7dxUJ_jMneuM0QMnnsQwdwgUTP2-eXAuLIFIzfQLQkbjQsfHmhk6Xz3/exec` | Standard Ford Energy onboarding badge intake. |
| `PERMANENT_BADGE_QR_URL` | `https://kyblueoval.github.io/Ford-Energy-VISTA/shared/assets/permanent-badge-intake-qr.png` | Hosted branded QR image used in visitor email. |
| `PERMANENT_BADGE_VISITOR_EMAIL_ENABLED` | `YES` | Sends the authorization and onboarding instructions to the visitor. |
| `PERMANENT_BADGE_SECURITY_EMAIL_ENABLED` | `NO` until recipients are configured, then `YES` | Controls Ford Global Security delivery. |
| `PERMANENT_BADGE_SECURITY_EMAILS` | Comma-separated approved email addresses or distribution lists | Global Security recipients. |

The security email switch intentionally defaults to `NO`. Enter and verify the approved Global Security distribution address before changing it to `YES`.

## Test sequence

1. Use an Approved, Checked In, or Checked Out visitor that has both an email address and saved visitor photograph.
2. Sign in to the Sponsor & Approver Portal and open the visitor record.
3. Select **Request Permanent Badge**.
4. Choose the badge type, enter required access, expected visit pattern, and business justification, then confirm the authorization.
5. Confirm a new row appears in `PermanentBadgeRequests` with status `Authorized - Pending Security Processing`.
6. Confirm the visitor receives the onboarding email containing the intake hyperlink and branded QR code.
7. After enabling the security notification setting, confirm the configured Global Security recipients receive the visitor name, company, photograph, badge type, access requirements, and Sponsor attribution.
8. Open Administration and select **Permanent Badge Authorizations**.
9. Move the request to **In Production**, then **Issued**. Enter the permanent badge number and scan or enter its UID.
10. Verify the status changes in `PermanentBadgeRequests` and the related actions appear in `VisitActivity` and `AuditLog`.

## Governance and safeguards

- Only active Sponsors, Approvers, Administrators, and Super Administrators with Sponsor Portal permission can create an authorization.
- The visitor must already be approved or have completed the applicable visit.
- A visitor email address and VISTA visitor photograph are required.
- VISTA blocks a second active authorization for the same visit or visitor email.
- Permanent credential requests are separate from the temporary visitor `BadgeInventory` workflow.
- Every authorization and processing change is attributed to the signed-in VISTA user and timestamped.
