# VISTA 2.6.3 — Recurring Visitor Term Governance

## What changed

The Sponsor & Approver scheduling form now asks whether the request is a **One-time visit** or a **Weekly recurring visit**. For a weekly series, the sponsor selects the last weekly arrival date. VISTA displays the exact number of separate visitor requests before submission and creates one request every seven days, including the first arrival date.

The previous values did not mean visits per week. For example, “12 weekly visits” meant 12 total visits, spaced one week apart. Those ambiguous presets have been removed.

## Ninety-day control

`SPONSOR_VISIT_TERM_MAX_DAYS` is added to the Config worksheet with a default value of `90`. Neither a one-time visit period nor a weekly visitor series may extend beyond that term. The backend enforces an absolute ceiling of 90 days; the Config value may be lowered for a stricter local standard. Longer access arrangements must be evaluated through the permanent Ford Energy badge process after the visitor's initial request is approved.

A 90-day term creates weekly requests on day 0, 7, 14, and so on through day 84: **13 total weekly requests**. Every occurrence receives its own Visit ID, confirmation number, visitor intake email, approval decision, and audit history.

## Deployment

1. Replace the deployed Apps Script `Code.gs` with `apps-script/Code.gs` from this build.
2. Save and run `setupVista()` once. This adds `SPONSOR_VISIT_TERM_MAX_DAYS` without changing existing production Config values.
3. Create a new Apps Script web-app deployment version while preserving the existing URL.
4. Publish the repository files to GitHub Pages.
5. Hard-refresh the Sponsor & Approver Portal and confirm the footer shows Version 2.6.3.

## Prove-out

1. Select **One-time visit** and confirm VISTA creates exactly one Submitted request.
2. Enter a one-time visit period longer than 90 days and confirm VISTA routes it to permanent-badge review instead of creating the request.
3. Select **Weekly recurring visit**, choose a term end date 28 days after the first date, and confirm the preview shows 5 weekly requests (day 0 through day 28).
4. Submit the series and confirm five separate confirmations and audit entries are created.
5. Test a term end date exactly 90 days after the first date and confirm VISTA permits the 13 weekly occurrences through day 84.
6. Test a term end date 91 days after the first date and confirm VISTA blocks submission with permanent-badge review guidance.
7. Open an approved visitor record and confirm **Request Permanent Badge** remains available for extended or frequent access.
