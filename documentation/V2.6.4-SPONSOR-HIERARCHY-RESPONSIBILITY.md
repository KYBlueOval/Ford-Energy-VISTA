# VISTA 2.6.4 — Sponsor Hierarchy & Responsibility UI

## Purpose

This milestone establishes a governed Sponsor accountability chain and replaces the cramped responsible-person control in the Sponsor Portal.

The hierarchy is:

1. Plant Leadership
2. OCM Sponsor / LL5
3. Primary Sponsor or requestor
4. Visitor

Operational responsibility may still be assigned to another salaried VISTA user for day-of-visit supervision and arrival notifications. Primary Sponsor accountability is retained.

## Deployment

1. Replace Apps Script `Code.gs` with the Version 2.6.4 file.
2. Run `setupVista()` once. This appends the new OCM Sponsor columns to `SponsorLeadership` without deleting or replacing existing rows.
3. Save Apps Script and create a new web-app deployment version while retaining the production web-app URL.
4. Push the repository files to GitHub Pages.
5. Hard-refresh Administration and the Sponsor & Approver Portal.

Existing Apps Script configuration values and production frontend configuration files are preserved.

## Prove-out

1. Sign in to Administration and open Sponsor Leadership Hierarchy.
2. Create a hierarchy with three distinct VISTA users: Plant Leader, OCM Sponsor / LL5, and Primary Sponsor.
3. Verify the new relationship displays as a four-level path ending in Sponsored Visitors.
4. Sign in as the OCM Sponsor and verify the assigned Sponsor's visitors and leadership reports are visible.
5. Open a visitor and verify the responsibility card is stacked, readable, and shows the configured hierarchy.
6. Select Assign Responsible Person, assign an eligible salaried VISTA user, and verify the activity and audit history.
7. Confirm legacy hierarchy rows remain visible and are marked as requiring OCM setup.
