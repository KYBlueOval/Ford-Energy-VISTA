# VISTA 2.3.4 — Handoff Resolution and Escalation

## Keep existing roster worksheets

Leave `FrontDesk`, `Security`, `Sponsors`, and `Users` in place. `Users` remains the authoritative identity table. The roster sheets remain supported compatibility sources and are not deleted or rewritten by this release.

## Deployment

1. Replace the Apps Script `Code.gs` with `apps-script/Code.gs` from this release.
2. Save the Apps Script project.
3. Run `setupVista()` once. It adds the new columns to `ShiftHandoffs` without deleting existing rows or changing production configuration values.
4. Create a new web-app deployment version and retain the existing web-app URL.
5. Deploy the repository contents to GitHub Pages.
6. Hard-refresh the application with `Ctrl + F5`.

## Test sequence

1. Record a handoff from Security Operations with at least one open accountability item.
2. Sign in as the incoming Security, Front Desk, Supervisor, or Administrator account.
3. Select `Acknowledge`, verify the assigned follow-up owner, and confirm.
4. Confirm the workflow state changes from `Pending` to `Acknowledged` and records the officer and timestamp.
5. Confirm the open-duration indicator is displayed and any existing assigned owner is preserved.
6. Enter resolution notes and select `Resolve`.
7. Confirm the workflow state changes to `Resolved` while the original onsite and badge counts remain unchanged.
8. Record another handoff and sign in as Security Supervisor, Admin, or Super Administrator.
9. Select `Escalate`, enter the assigned owner and escalation reason, and confirm the Supervisor Attention indicator appears.
10. Sign in as a standard Security or Front Desk account and confirm the Escalate action is not available.
11. Verify `AuditLog` contains `SHIFT_HANDOFF_ACKNOWLEDGED`, `SHIFT_HANDOFF_ESCALATED`, and `SHIFT_HANDOFF_RESOLVED` events.

## Regression checks

- Existing v2.3.3 handoffs display as Pending and remain actionable.
- Visitor approval, check-in, badge assignment, photo loading, checkout, and badge condition workflows remain operational.
- No existing sheet rows, folder IDs, authentication settings, web-app URLs, or Ford Energy assets are replaced.
