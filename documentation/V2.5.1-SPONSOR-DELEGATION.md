# VISTA 2.5.1 — Sponsor Delegation & Coverage

## Outcome

Sponsors and Approvers can assign a date-bounded substitute approver for vacation, shift coverage, project support, or other absences. Delegated access is enforced by the Apps Script backend and never grants Administration, Security Operations, check-in, checkout, badge, reporting, or configuration permissions.

## Data and configuration

Running `setupVista()` adds the `SponsorDelegations` worksheet with no changes to existing records. It also adds this Config key when missing:

`SPONSOR_DELEGATION_MAX_DAYS | 90`

Existing Config values are preserved.

## Rules

- Both the primary sponsor and delegate must be active VISTA users with role `Sponsor` or `Approver` and a valid email address.
- A sponsor cannot delegate to the same account.
- Coverage must have a valid start and end and cannot exceed the configured maximum.
- Overlapping assignments between the same sponsor and delegate are rejected.
- Coverage is effective only within its stored start and end date/time.
- The primary sponsor, delegate, or an Administrator can cancel active coverage.
- Delegated approvals, denials, cancellations, visitor updates, photographs, and activity access remain server-scoped and audited.

## Deployment

1. Replace the Apps Script project `Code.gs` with `apps-script/Code.gs`.
2. Save the Apps Script project.
3. Run `setupVista()` once.
4. Confirm the `SponsorDelegations` worksheet and `SPONSOR_DELEGATION_MAX_DAYS` Config key exist.
5. Create a new version of the existing Apps Script web-app deployment while retaining its URL.
6. Allow GitHub Pages to deploy and hard-refresh the Sponsor Portal.

## Proof-out

1. Confirm two active Sponsor or Approver users have distinct emails, usernames/PINs, and optional badge UIDs.
2. Sign in as the primary sponsor and create seven-day coverage for the substitute.
3. Confirm the assignment appears as Active and `SPONSOR_DELEGATION_CREATED` appears in `AuditLog`.
4. Sign in as the substitute and confirm the primary sponsor's assigned requests appear with a `Covering for` label.
5. Approve one delegated request and verify the status, visitor email, activity entry, and acting substitute identity.
6. Confirm an unrelated sponsor's request remains unavailable, including direct photo and activity requests.
7. Cancel the coverage and confirm those delegated requests disappear immediately.
8. Create future coverage and confirm it appears as Scheduled but does not grant early access.
