# VISTA 2.4.2 — EV Administration Approval and Facilities Integration

## Updating the charging policy

The EV request page reads its policy from the active row in the `EVChargingPolicies` worksheet.

| Worksheet column | Page content |
| --- | --- |
| `Title` | Policy heading |
| `SitePolicy` | Site Policy panel |
| `StateAndUseTerms` | Rules and Regulations / Terms of Use panel |
| `Version` | Version recorded with the employee acknowledgement |
| `EffectiveDate` | Effective date displayed on the request |
| `Active` | Only a row marked `Yes` is presented |

Policy items should be entered as separate lines in the cells. Each nonblank line becomes one check-marked rule on the page.

When policy wording changes:

1. Preserve the previous row for audit history.
2. Create a new row or copy the previous row.
3. Update `Version`, `EffectiveDate`, `SitePolicy`, and `StateAndUseTerms`.
4. Set the previous row to `Active = No`.
5. Set the new row to `Active = Yes`.
6. Keep only one active row.

VISTA calculates the content hash when the page opens and validates it again at submission. Applicants who opened an older version must refresh and acknowledge the new text.

## Administration approval

The Administration Console now contains **Employee Charging Requests**.

Authenticated Admin and Super Administrator users can:

- Search employee, CDSID, manager, confirmation, and license plate
- Filter pending, approved, and denied requests
- Approve a pending request
- Deny a pending request with required comments
- View decision source and Facilities delivery status

Manager email-link approval remains supported. The request records `Manager Email Review` or `VISTA Administration` in `DecisionSource`.

## Onboarding Badge UID lookup

On approval, VISTA opens the configured onboarding spreadsheet and searches:

- Worksheet: `Onboarding_Raw_Data`
- Employee name: column D
- Badge UID: column AQ

The supplied onboarding spreadsheet ID is:

```text
1QSJN0Sx5okbIgT47R2zoze518Lu994ypyTHocevzSjI
```

Matching first uses the complete normalized employee name. If the request contains only first and last name while onboarding contains a middle name or initial, VISTA may use a first-and-last match only when it resolves safely to one Badge UID. VISTA will not guess when multiple different Badge UIDs are possible.

Possible results include:

- `Found`
- `Found · First/Last`
- `Not Found`
- `Badge UID Missing`
- `Ambiguous`
- `Lookup Failed`

The Google account executing the Apps Script web app must have at least Viewer access to the onboarding spreadsheet.

## Config values

Running `setupVista()` adds these keys only when missing:

| Key | Default | Purpose |
| --- | --- | --- |
| `EV_FACILITIES_EMAIL_ENABLED` | `NO` | Enables Facilities emails after an EV request is approved |
| `EV_FACILITIES_EMAILS` | blank | One or more recipients separated by commas or semicolons |
| `EV_ONBOARDING_SPREADSHEET_ID` | onboarding database ID | Spreadsheet used for Badge UID lookup |
| `EV_ONBOARDING_SHEET_NAME` | `Onboarding_Raw_Data` | Worksheet used for lookup |

Recommended production example:

```text
EV_FACILITIES_EMAIL_ENABLED    YES
EV_FACILITIES_EMAILS           facilities@example.com; ev-program@example.com
EV_ONBOARDING_SPREADSHEET_ID   1QSJN0Sx5okbIgT47R2zoze518Lu994ypyTHocevzSjI
EV_ONBOARDING_SHEET_NAME       Onboarding_Raw_Data
```

Use actual approved distribution addresses in production.

## Spreadsheet additions

`setupVista()` appends these columns to `EVChargingRequests`:

- `DecisionSource`
- `OnboardingBadgeUID`
- `OnboardingLookupStatus`
- `FacilitiesNotificationSent`
- `FacilitiesNotificationStatus`
- `FacilitiesNotificationRecipients`
- `FacilitiesNotificationAt`
- `FacilitiesNotificationError`

Existing request records and Config values are preserved.

## Deployment

1. Replace the Apps Script project's `Code.gs`.
2. Save the project.
3. Run `setupVista()` once.
4. Approve requested spreadsheet and email permissions.
5. Confirm the new Config keys and request columns exist.
6. Give the Apps Script execution account Viewer access to the onboarding spreadsheet.
7. Enter the approved Facilities recipients.
8. Set `EV_FACILITIES_EMAIL_ENABLED` to `YES`.
9. Create a new version of the existing web-app deployment.
10. Preserve the existing web-app URL and access settings.
11. Hard-refresh Administration with `Ctrl + F5`.
12. Confirm the footer shows `Version 2.4.2`.

## Proof test

1. Submit an EV request using an employee name that exactly matches onboarding column D.
2. Sign in to Administration as an Admin or Super Administrator.
3. Find the request under **Employee Charging Requests**.
4. Approve it.
5. Confirm the employee receives the approval decision.
6. Confirm Facilities receives the approval message.
7. Verify the email contains the correct employee name and Badge UID from column AQ.
8. Confirm `EVChargingRequests` records the decision source, Badge UID, lookup status, recipients, sent status, and sent time.
9. Confirm `EVChargingActivity` contains `ADMIN_APPROVED` and `FACILITIES_APPROVAL_EMAIL_SENT`.
10. Confirm `AuditLog` contains the authenticated administrator and both actions.
11. Submit another request and verify Administration denial with required comments.
12. Test a nonmatching employee name and confirm approval remains successful while Facilities receives a manual-verification warning.

## Failure safety

- Onboarding lookup is read-only.
- VISTA does not modify the onboarding spreadsheet.
- An ambiguous name never selects an arbitrary Badge UID.
- Approval is not rolled back if onboarding lookup or Facilities email fails.
- Failures are retained for follow-up in the request, EV activity, and global audit history.
