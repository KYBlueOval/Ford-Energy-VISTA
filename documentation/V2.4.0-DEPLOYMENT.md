# VISTA 2.4.0 — EV Charging Access Requests

## Included

- A fourth VISTA Home workspace: **EV Charging Access**.
- Two-step Ford Energy / Ford Motor Company employee intake.
- Employee, manager, and vehicle information.
- Versioned Ford Energy BlueOval charging policy and Terms of Use.
- Policy acknowledgement with version, content hash, and timestamp.
- Employee confirmation number and email.
- Secure manager approval email with a time-limited review token.
- Manager CDSID verification and one-time approval or denial.
- Employee decision email and optional EV program notification.
- Dedicated request and event history plus global VISTA audit entries.

## Spreadsheet migration

Replace `apps-script/Code.gs`, save, and run:

```javascript
setupVista()
```

The setup is additive. It creates:

- `EVChargingRequests`
- `EVChargingActivity`
- `EVChargingPolicies`

It also appends these Config keys only when they do not already exist:

- `EV_CHARGING_REQUEST_URL`
- `EV_MANAGER_REVIEW_DAYS`
- `EV_NOTIFICATION_EMAIL`

Existing Config values and existing visitor-management sheets are not replaced.

## Configuration

Recommended values:

| Key | Value |
|---|---|
| `EV_CHARGING_REQUEST_URL` | `https://kyblueoval.github.io/Ford-Energy-VISTA/ev-charging-request/` |
| `EV_MANAGER_REVIEW_DAYS` | `14` |
| `EV_NOTIFICATION_EMAIL` | Optional mailbox or distribution list for EV program notifications |

## Policy approval

`setupVista()` seeds an initial operational policy template in `EVChargingPolicies`.

Before production use:

1. Have the Ford Energy policy owner, Legal, EHS, Security, and Facilities review the wording.
2. Update `SitePolicy` and `StateAndUseTerms` as directed.
3. Change `Version` when policy content changes.
4. VISTA calculates the submitted content hash from the active policy text when the request is opened and again when it is submitted.

Only one policy should normally have `Active` set to `Yes`.

## Apps Script deployment

1. Run `setupVista()`.
2. Approve any new Mail and spreadsheet permissions.
3. Create a new web-app deployment version.
4. Retain the existing web-app URL.
5. Confirm `ev-charging-request/config.js` uses that same URL.
6. Publish the repository to GitHub Pages.
7. Hard-refresh the Home Dashboard and EV Charging Access page.

## Proof test

1. Open `/ev-charging-request/`.
2. Confirm the Home Dashboard displays four workspace cards.
3. Complete Step 1 with test Ford employee and manager email addresses.
4. Review Step 2, the policy version, summary, and Terms of Use.
5. Acknowledge and submit.
6. Confirm a row appears in `EVChargingRequests` with `Pending Manager Approval`.
7. Confirm `EVChargingActivity` records `REQUEST_SUBMITTED`.
8. Confirm the employee receives a confirmation email.
9. Confirm the manager receives a secure review email.
10. Open the manager link and enter the matching manager CDSID.
11. Approve the request.
12. Confirm the request becomes `Approved`.
13. Confirm the employee receives a decision email.
14. Confirm `EVChargingActivity` records `MANAGER_APPROVED`.
15. Confirm `AuditLog` contains `EV_CHARGING_REQUEST_SUBMITTED` and `EV_CHARGING_MANAGER_APPROVED`.
16. Repeat with a second request and test denial plus manager comments.

## Security behavior

- The usable manager token is sent only in the approval link.
- Only its SHA-256 hash is stored in the spreadsheet.
- The link expires after the configured number of days.
- The manager must enter the CDSID recorded on the request.
- An approved or denied request cannot be decided again from the same link.
- Duplicate browser submissions use a client submission ID to avoid duplicate rows.
