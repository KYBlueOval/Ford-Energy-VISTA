# VISTA 2.4.5 — Supervised Manual Visitor Check-In

## Purpose

Security Operations can now create and immediately check in a walk-in visitor who did not complete pre-registration.

The workflow captures visitor identity, sponsor, visit, vehicle, photograph, visitor badge, expected departure, ID-retention status, sponsor notification choice, and operational notes.

## Authorization rules

- FrontDesk can open and complete the intake form.
- FrontDesk cannot create the record or check the visitor in until a Security Supervisor, Admin, or Super Administrator authorizes the operation.
- Authorization can use the supervisor's VISTA badge or username and PIN.
- A Security Supervisor, Admin, or Super Administrator already signed in does not receive a second authorization prompt.
- Ordinary Security accounts cannot launch or call the manual-override workflow.
- The server validates the authorizing account and role. Hiding or modifying browser controls cannot bypass authorization.

## Recorded evidence

The workflow writes the visitor to `VisitRequests`, the lifecycle events to `VisitActivity`, and both the initiating and authorizing identities to `AuditLog`.

Because the visitor did not complete pre-registration, VISTA records `Manual Override - Not Collected` for the agreement completion status and does not create false agreement acknowledgements.

## Deployment

This milestone includes an Apps Script update.

1. Replace the deployed Apps Script `Code.gs` with `apps-script/Code.gs` from this repository.
2. Save the Apps Script project.
3. Create a new web-app deployment version while preserving the existing deployment URL.
4. Publish the repository contents to GitHub Pages.
5. Sign out of VISTA and sign back in so the new role permissions are loaded into the browser session.
6. Hard-refresh Security Operations with `Ctrl + F5`.

No `setupVista()` run and no spreadsheet schema migration are required.

## Proof test — elevated user

1. Sign in to Security Operations as Security Supervisor, Admin, or Super Administrator.
2. Select **Manual Visitor Check-In**.
3. Complete the required visitor, sponsor, visit, and badge fields.
4. Review the manual-override disclosure.
5. Confirm the current session is shown as the authorizer.
6. Select **Create Record & Check In**.
7. Confirm the visitor appears as Checked In, the badge is Issued, and live accountability updates.

## Proof test — Front Desk supervised submission

1. Sign in as FrontDesk and open **Manual Visitor Check-In**.
2. Complete the intake form and select **Review & Authorize**.
3. Confirm VISTA requires supervisor authorization.
4. Attempt authorization with an ordinary Security account and confirm it is denied.
5. Authorize with a Security Supervisor badge or PIN.
6. Confirm the visitor record and check-in complete.
7. Verify `VisitActivity` contains manual registration and check-in events.
8. Verify `AuditLog` identifies both the Front Desk initiator and the elevated authorizer.

## Additional checks

- Confirm an unavailable badge is rejected.
- Confirm an unknown visitor badge requires both the registration checkbox and a new badge number.
- Confirm sponsor arrival email delivery or failure status is recorded.
- Confirm the form remains usable on a phone-width screen.
