# VISTA 2.5.5 — Sponsor Performance & Leadership Outlook

## Deployment

1. Replace the deployed Apps Script project `Code.gs` with `apps-script/Code.gs` from this repository.
2. Run `setupVista()` once. Existing values and records are preserved; the new VisitRequests columns and `VISITOR_ADVANCE_NOTICE_DAYS` Config key are added when absent.
3. In the Config worksheet, set `VISITOR_ADVANCE_NOTICE_DAYS` to the required whole number of calendar days, such as `7` or `14`.
4. Create a new Apps Script web-app deployment version and retain the existing web-app URL.
5. Publish the repository to GitHub Pages and hard-refresh the Public Registration, Sponsor Portal, Security Operations, and Administration pages.

## Proof-out sequence

1. Create one request outside the configured advance-notice window. Confirm the public form displays a late-request warning and still permits submission.
2. Create one request that meets the configured notice standard.
3. Open the late request in the Sponsor Portal. Confirm its exception is displayed.
4. Attempt approval with any of the three approval fields empty. Confirm approval is blocked.
5. Enter approval notes, parking lot assignment, and office/seating assignment; approve the visit.
6. Confirm the visitor approval email includes the parking and office/seating assignments.
7. Repeat an approval from Security Operations using an authorized non-sponsor account. Confirm it is recorded as a manual approval.
8. In Administration, verify the Sponsor & Approver Performance scorecard shows on-time, late, compliance rate, manual approvals, decision time, and lead time.
9. Under Reports & Export, generate and export:
   - Sponsor / Approver Performance
   - Two-Week Leadership Outlook
10. Confirm the AuditLog and VisitActivity entries retain the approving user and outcome.

## New VisitRequests fields

- `AdvanceNoticeRequiredDays`
- `AdvanceNoticeActualDays`
- `AdvanceNoticeHours`
- `AdvanceNoticeCompliant`
- `AdvanceNoticeFlaggedAt`
- `SponsorApprovalNotes`
- `ParkingLotAssignment`
- `OfficeSeatingAssignment`
- `ApprovalDecisionAt`
- `ApprovalResponseMinutes`
- `ApprovalDecisionBy`
- `ApprovalDecisionRole`
- `ApprovalSource`
- `ApprovalManualOverride`

Older records remain supported. Analytics derives advance-notice compliance from `CreatedAt`, `StartDate`, and `ArrivalTime` when the new stored fields are absent.
